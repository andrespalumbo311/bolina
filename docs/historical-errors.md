## 1. Build Pipeline, OCI Layers & CI/CD

| Error Class / Technical Challenge | Root Cause (Abstract) | Preventive Action / Architectural Pattern |
| :--- | :--- | :--- |
| **Vital Directory Persistence** | Git does not track empty directories; deleting the last file in a mapped directory breaks container `COPY` instructions. | Always maintain a `.keep` file in directories that must persist in the repository structure. |
| **Monolithic Containerfile Build Bottleneck** | Large monolithic `RUN` blocks in `Containerfile` force total layer re-compilation on every edit, slowing down local/CI builds and preventing partial layer caching. | Modularize the build into discrete scripts in `build_files/` (`01-copr`, `02-kernel`, `03-cli-packages`, `04-desktop-packages`, `05-system-config`). Enable `--cache-from` on PR/push events and `--no-cache` on scheduled daily builds. |
| **Non-Deterministic Layer Invalidation & ARG Cache Busting** | Dynamic timestamps (`date`), `sbsign` embedding OpenSSL `signingTime`, `@${SOURCE_DATE_EPOCH}` in `faketime` (`parse_ft_string` failure), DNF5 runtime logs/WAL, and declaring `ARG SHA_HEAD_SHORT` early in Stage 2 invalidate layer hashes. | 1. Convert epoch via `date -u -d "@${SOURCE_DATE_EPOCH}" "+%Y-%m-%d %H:%M:%S"` and run `faketime "${SIGN_DATE}" sbsign`.<br>2. Declare volatile `ARG`s immediately before consumption.<br>3. Purge `/var/lib/dnf`, `/var/log/dnf*`, and `/usr/lib/sysimage/libdnf5/transaction_history*` in `05-system-config.sh`.<br>4. Use epoch `1700000000` for `dracut --reproducible`. |
| **Fontconfig Cache Invalidation Failure & Distrobox Collision** | Purging `/usr/lib/fontconfig/cache/*` or bootc stripping it via `CACHEDIR.TAG` leaves system without cache. bootc normalizes font timestamps to epoch 0 (`mtime=0`), causing host to permanently accept poisoned truncated caches (`~/.cache/fontconfig/`) generated by Distrobox containers sharing `$HOME`, hiding `Noto Color Emoji`. | 1. Strip `CACHEDIR.TAG` after `SOURCE_DATE_EPOCH=1700000000 fc-cache -s -f` in `05-system-config.sh`.<br>2. In `distrobox.conf` (conditioned on `${0##*/}` matching `distrobox-create*`), isolate cache via `container_manager_additional_flags="--tmpfs ${HOME}/.cache/fontconfig:rw"` (avoid unconditional flags that break `distrobox-enter` with code 125).<br>3. Add font dir `<dir>/usr/share/fonts/google-noto-color-emoji-fonts</dir>` in `/etc/fonts/conf.d/`.<br>4. Run `fc-cache -rf` and wipe `~/.cache/fontconfig`. |
| **Chunked-OCI CI Overhead & Chunk Drift** | Running 127-layer chunked-oci composition on PRs wastes 40-60 min of CI compression. Without aligning to previous builds, minor package shifts alter chunk boundaries, forcing clients to re-download unchanged layers on upgrade. | 1. Make rechunking conditional on release pushes (`if: github.event_name != pull_request`).<br>2. Set `--max-layers 64`.<br>3. Pass `--previous-build docker://${REGISTRY}/${NAME}:${TAG}` to align chunk boundaries with remote manifests for 0-byte re-uploads. |
| **Buildah `--cache-from` URI Tag Syntax Error** | Passing a repository URI with a tag (e.g., `image:latest`) to `buildah bud --cache-from` causes exit code 125 (`repository must contain neither a tag nor digest`). | Specify `--cache-from` using only the repository URI base without tags or digests (e.g., `${{ env.IMAGE_REGISTRY }}/${{ env.IMAGE_NAME }}`). |
| **Buildah Layer Cache Loss vs CI Disk I/O Bottleneck** | Pulling a 10GB raw layer cache image and passing `--layers` on GitHub Actions runner VMs creates massive disk I/O and network bottlenecks, doubling build times. | Build directly in memory/flat storage without remote layer cache pulling on CI. Maintain deterministic initramfs, Git SHA `os-release`, and pinned binary versions to guarantee minimal delta downloads on the client host via `bootc upgrade`. |
| **CI Storage Driver Degradation & Rechunker RPC Failure** | Setting `STORAGE_DRIVER: overlay` in GitHub Actions `env:` is cleared by `sudo`. Specifying `--output oci:/path` to bootc rechunker triggers RPC errors in `skopeo` proxy (`OpenImageOptional: no such file or directory`) expecting existing OCI layout. | 1. Write `/etc/containers/storage.conf` on runner filesystem after purging `/var/lib/containers/storage`.<br>2. Use native `--output containers-storage:localhost/chunked-${IMAGE_NAME}` within rechunker container.<br>3. Set `vm.swappiness=10`. |
| **OCI Runtime Mount Target Failure & Redundant Commits** | In bootc images, `/mnt` and `/root` are symlinks to `/var/mnt` and `/var/roothome` in unbooted container rootfs. Binding host paths to them triggers `crun: openat2: No such file or directory`. Running `buildah commit` to clean `/run` and `/tmp` rewrites the full 8GB image to disk. | 1. Mount host scratch files strictly into `/tmp` (e.g. `REGISTRY_AUTH_FILE=/tmp/auth.json`).<br>2. Clean temporary artifacts in `/run` and `/tmp` in-place within build scripts (`05-system-config.sh`) before finalizing the image. |
| **Runner Storage Driver Mismatch & `--layers` Latency** | Ubuntu 24.04 runners with unconfigured `/var/lib/containers/storage` trigger exit code 125 (`graph driver "" does not match "overlay"`). In addition, passing `--layers` to `buildah bud` commits layers on every instruction (including consecutive `COPY` steps), adding 12-15 min of CI latency. | 1. Purge pre-existing storage (`rm -rf /var/lib/containers/storage`) before writing `storage.conf`.<br>2. Use `buildah tag` instead of `podman tag`.<br>3. Omit `--layers` in CI container builds to execute multi-stage file operations at in-memory speed. |
| **Symlinked Path Copy Failure (`/usr/local`)** | GNU `cp -r` in shell scripts fails with `cannot overwrite non-directory '/usr/local' with directory` on Fedora Atomic because `/usr/local` is a symlink to `/var/usrlocal`. | Use native Buildah/Docker `COPY etc /etc` and `COPY usr /usr` directly in the `Containerfile`. Buildah handles symlinks natively and merges directory contents cleanly without breaking symlink targets. |
| **Ephemeral Path Persistence** | Including files or directories in `/run`, `/tmp`, or `/var` directly in the image triggers `bootc lint` warnings and violates stateless principles. | **Never** persist ephemeral content in the image. Use `/usr/lib/tmpfiles.d/*.conf` to declare required directories or files, ensuring the system creates them dynamically at runtime. |
| **Broken Tmpfiles Symlinks** | Declaring `L+` (link) in `tmpfiles.d` to a path that is already occupied by a file copied via `Containerfile` creates a conflict or broken reference. | **Prefer** direct `COPY` in `Containerfile` for static configs and use `tmpfiles.d` only for ephemeral/stateful paths (`/var`, `/run`). Avoid overlapping declarations. |
| **Tarball Path Structure Mismatch** | Failure to account for nested directories (e.g., `bin/` or versioned folders) within release tarballs leads to broken `COPY` instructions in multi-stage builds. | Always use `tar -tf` to audit archive structures. Use `--strip-components` to flatten the directory hierarchy or adjust the `COPY` source paths to match actual extraction results. |
| **Unchecked Pipe Execution & Redundant Builder Dependencies** | Piping `curl` output directly to `sh` without `-f` causes the shell to execute HTTP error pages. Conversely, running `dnf install` in the builder stage for utilities already present in `base-main` (`curl`, `jq`, `tar`, `xz`) wastes ~15s and 85MB of repo metadata downloads per build. | **Always** use `curl -fsSL` when piping to a shell. Verify base image package manifests before invoking DNF in multi-stage builds to avoid redundant installations of pre-baked tools. |
| **Inconsistent Release Assets (Verification Failure)** | Relying on external signature files (`.sig`) or checksum files (`.sha256`) causes 404 errors if projects change their release naming conventions or stop providing them. | **Use the GitHub API `digest` field** to programmatically retrieve and verify the SHA256 of any release asset. This provides a unified, version-agnostic, and robust verification method that doesn't depend on sidecar files. |
| **Stale Direct Binaries** | Using hardcoded versions and checksums for external binaries (like `sudo-rs`) leads to security debt and manual maintenance overhead. | **Always** use the GitHub API to dynamically retrieve the `latest` release. Extract the `digest` (SHA256) directly from the API metadata to automate integrity verification without hardcoding hashes. |
| **GitHub API Anonymous Rate Limiting in CI Multi-Asset Builds** | Querying `api.github.com/repos/...` via anonymous `curl -fsSL` across multiple asset downloads rapidly exceeds GitHub's unauthenticated IP rate limit (60 requests/hr per runner IP) during rapid successive CI runs, resulting in HTTP 403 (`curl: (22) The requested URL returned error: 403`). | 1. Accept `ARG GITHUB_TOKEN=""` in the builder stage and wrap API calls in a helper (`gh_curl`) that conditionally appends `-H "Authorization: Bearer $GITHUB_TOKEN"` when present while remaining backwards-compatible with anonymous local builds. 2. Pass `--build-arg GITHUB_TOKEN="${{ secrets.GITHUB_TOKEN }}"` in the CI workflow `buildah bud` invocation. |
| **Dependabot Dockerfile Ecosystem Binary Release Limitation** | Dependabot's `dockerfile` ecosystem only updates `FROM` base images and cannot map generic `ARG` variables to GitHub release tags. | Use **Renovate Bot** with `# renovate: datasource=github-releases depName=...` comments and `customManagers` regex pattern in `renovate.json5`. |
| **Renovate Custom Regex Keyword Collision (`packageName` vs `depName`)** | In Renovate's `regexManager`, `packageName` is a reserved capture group defining the upstream registry lookup identifier and takes precedence over `depName`. Capturing shell variable prefixes (e.g. `(?<packageName>.*?)_VERSION`) forces Renovate to query the upstream datasource with an invalid or non-existent name rather than the repository identifier, causing silent lookup failures. | In Renovate regex managers, reserve `(?<depName>...)` for the repository path (`owner/repo`) and match shell variables using non-reserved patterns (e.g. `ARG [A-Za-z0-9_]+_VERSION=...`), avoiding unintended assignments to `packageName`. |
| **Renovate Branch Staleness & Rebase Suppression (`rebaseWhen: never`)** | Setting `rebaseWhen: "never"` prevents Renovate from rebasing open PR branches when parallel PRs merge into `main`. This traps superseded update paths (such as older patch/minor streams or digest updates superseded by major version bumps) in perpetual merge conflict states instead of letting the bot rebase and auto-close them. | Always set `rebaseWhen: "auto"` (or omit the setting to inherit the default) in Renovate configuration to enable automatic rebasing against the base branch and dynamic retirement of obsolete update branches. |
| **Two-Tier Image Architecture & MOK Segregation** | Retaining UEFI Secure Boot MOK signing logic, secrets, and public certificates within the public base image creates unnecessary secret dependencies, PR dummy-key overhead, and leaks hardware-specific deployment assumptions. | Segregate all MOK signing, certificate storage, and vmlinuz signature mutations exclusively to downstream private fleet micro-layers (`bolina-fleet`). Pre-install only user-space signing utilities (`sbsigntools`, `libfaketime`) in the base image so downstream layers avoid running package managers. |
| **`os-release` UTF-8 Null Byte Corruption on Append** | Appending (`>>`) variables to `/usr/lib/os-release` during container builds without sanitizing null padding or existing keys inserts `0x00` bytes. During atomic upgrade, `ostree-finalize-staged.service` fails with `Invalid UTF-8` and the bootloader rejects switching to the new deployment. | Run `sed -i '/^IMAGE_ID=/d'` and sanitize null bytes with `tr -d '\000'` on `/usr/lib/os-release` before writing new variables to ensure strict UTF-8 validity required by OSTree/bootc. |
| **Orphaned File References (Build Failure)** | Deleting or renaming a repository asset without updating all references in the build manifest (Containerfile, scripts) causes execution failures during the build process. | **Always** perform a global search (grep) for the filename or path of a deleted/renamed asset to identify and update all associated commands (e.g., `chmod`, `chown`, `COPY`). |
| **Missing Build Instruction (Syntax Error)** | Accidental removal of mandatory instructions (e.g., `RUN`, `COPY`) during surgical edits causes the build engine to interpret shell scripts as invalid keywords (e.g., `Error: Unknown instruction: IF`). | **Verify** that every functional block in the Containerfile is preceded by a valid instruction. Use `bootc container lint` locally or via simulation if possible after edits. |
| **Stale Context for Surgical Edits** | Attempting surgical file edits (e.g., via `replace`) using context derived from a state prior to a file system operation (like `git restore` or `git checkout`) causes tool failure due to mismatched content. | **Re-read files** or verify their current state after any git command that modifies the working tree before attempting further automated code changes. |
| **Build Environment Leakage** | Failing to isolate build caches (like `CARGO_HOME`) in multi-stage builds leads to permission errors or bloated layers. | Explicitly define and isolate build environment variables and cache directories within the `builder` stage. |
| **Repository Asset Persistence** | Over-aggressive manual cleanup of build artifacts can lead to the accidental deletion of tracked repository assets (like `.der` certificates). | Distinguish between untracked build secrets (to be removed) and tracked public assets (to be preserved) before executing cleanup commands. |
| **Touchscreen Ecosystem Multi-Binary Release Decoupling & CI Preservation** | Compiling heavy Wayland compositors with patchsets and desktop GUI configurators directly inside the primary OCI image build pipeline causes severe layer cache busting, inflates daily CI execution by 15-20 minutes, and triggers runner failure if downstream containers pull non-existent release tags before asset publication. | Decouple multi-binary packaging (`niri-tablet`, `wvkbd-mobintl`, `niri-tablet-easysetup`) into a dedicated GitHub Actions workflow triggered by upstream release cron/dispatch and push paths, publishing to dual release pointers (`niri-tablet-${UPSTREAM_TAG}` and `niri-tablet-latest`). Isolate the workflow from the container build using `paths-ignore` in `build.yml`. |
| **Shell Delimiter Ingestion of Inline Comments** | Using simple field splitting (`cut -d=`) on variable assignment lines containing trailing shell comments (`# ...`) appends the comment text into the extracted variable string, producing invalid Git branch or tag identifiers. | Use regex pattern matching with capture groups (e.g. `sed -E 's/.*_var=([a-zA-Z0-9._-]+).*/\1/'`) or strip inline comments prior to field splitting when parsing shell script or PKGBUILD definitions. |
| **Headless CI Stall on Interactive Service Restarts (`needrestart`)** | Installing complex system library dependencies (GLib, GTK4, PipeWire, Udev) triggers the Debian/Ubuntu `needrestart` hook, which stalls headless CI execution indefinitely while awaiting user keyboard input on curses interactive service restart prompts. | Explicitly purge `needrestart` (`sudo apt-get purge -y needrestart`) and enforce non-interactive flags (`DEBIAN_FRONTEND=noninteractive NEEDRESTART_MODE=l apt-get install -y --no-install-recommends`) on all Debian/Ubuntu headless package setups. |
| **Native Crate Development Headers Omission under `--no-install-recommends`** | Passing `--no-install-recommends` to Debian/Ubuntu `apt-get` drops transitive development headers (e.g. `libgdk-pixbuf-2.0-dev` required by `gtk4`/`gdk-pixbuf-sys`), triggering pkg-config build script failures during Rust crate compilation. | Audit `-sys` crate dependencies of GUI toolchains (GTK4, Adwaita) and explicitly declare all direct `.pc` providers (`libgdk-pixbuf-2.0-dev`) in the package list when disabling recommendations. |
| **Crate Feature Flag Version Mismatch with Runner Libraries** | A Rust crate declares a high minimum feature flag (e.g. `gtk4/v4_16`) while runner distributions provide a slightly older stable release (e.g. GTK 4.14 on Ubuntu 24.04), causing `*-sys` build script failures even when the codebase uses no new APIs. | Audit API requirements; relax version-specific Cargo features to match runner library versions (e.g. `sed -i 's/"v4_16"/"v4_14"/' Cargo.toml`) and re-generate locks during CI packaging. |
| **Upstream Release Tag Asset Drift & Unconditional File Copy** | A Git release tag points to an earlier commit in the upstream repository that predates auxiliary assets (e.g. `.desktop` files, icons) added subsequently on the main development branch. Unconditional file copy operations (`cp path/to/file`) fail with missing file errors despite successful source compilation. | Audit tag histories; clone the main repository branch or guard auxiliary file copies with conditional checks (`if [ -f ... ]`), providing automated fallbacks for desktop launcher metadata. |
| **Heredoc Zero-Indentation Column 0 YAML Scanner Collision** | In YAML multiline block scalars (`run: |`), unindented text at column 0 (such as raw heredocs `cat <<'EOF'`) abruptly terminates the multiline scalar and causes GitHub Actions / YAML parsers to throw a fatal `ScannerError` before any jobs can start. | Maintain uniform whitespace indentation throughout the script block or prefer `printf '%s\n' "..." > file` for file generation inside CI workflow definitions. |
| **Multi-Tag Storage Lock & CI Runner Disk Exhaustion** | Tagging multiple aliases (via `buildah tag`) on `localhost/<image>:latest` before `podman rmi localhost/<image>:latest` only untags the specific `:latest` reference while preserving the full image and all layers in `containers-storage`. In downstream steps like Chunked-OCI rechunking, runner disks exhaust available storage (0 bytes free). | Do not multi-tag intermediate images before rechunker cleanup; build only a single `:latest` tag and defer multi-tag generation to the final registry push step via Skopeo. |
| **Builder Stage Dependency Consolidation & Verification** | Downloading external assets (fonts, shell plugins) via unpinned `curl` or runtime `git clone` during Stage 2 layers introduces non-deterministic builds, security blindspots, and unnecessary network dependencies during system assembly. | Move all asset downloads into Stage 1 (`builder`) with explicit SHA256 checksum or `.digest` verification and Renovate Bot annotations, copying pre-verified assets into Stage 2 via `COPY --from=builder`. |
| **Dangling Build-Time Package Repositories (COPR)** | Leaving temporary or unused COPR repositories enabled in `/etc/yum.repos.d/` leaves stale repo metadata in the final image, increasing attack surface and causing failed repo syncs during post-install package operations. | Explicitly disable all enabled COPR repositories before running `dnf5 clean all` in `05-system-config.sh`. |
| **Two-Tier OCI Architecture & CI Quota Preservation** | Compiling system daemons from source inside private device repositories exhausts private GitHub Actions quotas (2,000 min/mo). Fleet micro-layers must remain fast (<1 min). | 1. Compile native daemons (`bolina-daemon`) in upstream public repo (`bolina`) with unlimited CI minutes.<br>2. Install static binaries into base image (`/usr/bin/bolina-daemon`).<br>3. Downstream private layers inherit binaries directly, limiting CI strictly to configuration overlays and kernel signing. |

## 2. Desktop Environment, Compositor (Niri) & Greeter (greetd)

| Error Class / Technical Challenge | Root Cause (Abstract) | Preventive Action / Architectural Pattern |
| :--- | :--- | :--- |
| **Locked Keyring on Wayland** | Compositors like Niri don't automatically unlock the GNOME Keyring. Incorrect XDG portal backend names (e.g. `gnome-keyring` instead of `gnome`) break Secret portal integration for Flatpaks. | 1. Configure PAM (`/etc/pam.d/greetd`). 2. Use `org.freedesktop.impl.portal.Secret=gnome` (not `gnome-keyring`). 3. Explicitly export `GNOME_KEYRING_CONTROL` to D-Bus/Systemd. |
| **SELinux Denials in greetd** | Custom PAM files for `greetd` without `pam_selinux.so` prevent the session from transitioning to the user context, blocking access to systemd units. | **Always** include `pam_selinux.so` (open/close) in custom PAM configs on Fedora-based systems to ensure correct context transition. |
| **Greetd PAM Auth Failure** | Using `substack system-auth` for the `greetd` user (who typically has no password) prevents the greeter from launching. | Use `pam_permit.so` in `/etc/pam.d/greetd` to allow the greeter user to initialize the session without a password. |
| **Greetd Service Account PAM Isolation** | Using global `pam_permit.so` to avoid greeter boot-loops bypasses authentication for all users. | Use `[success=done default=ignore] pam_succeed_if.so user = greetd` to skip auth exclusively for the greeter daemon, preserving full `system-auth` password/keyring/biometric authentication for real users. |
| **Greeter Input Group Missing** | Compositors like Niri running as the `greetd` user cannot access input devices without the `input` group. | **Always** add `greetd` to the `input` group in addition to `video` and `render` in the `Containerfile`. |
| **DMS-Greeter CLI Incompatibility** | Passing `--path` pointing to a config directory instead of the QML source directory causes an immediate crash of the greeter. | **Verify** CLI flags against official docs. Use `--cache-dir` for settings and omit `--path` unless using custom shell sources. |
| **Niri Spawn Path Failure** | Niri's `spawn-at-startup` does not expand `~`. Using relative or tilde paths causes startup to fail silently or crash the session. | Use `spawn-sh-at-startup` with `$HOME` for scripts located in user directories to ensure proper shell expansion. |
| **KDE Connect & Remote Input on Wayland (Niri)** | Remote input fails if `niri-portals.conf` maps `RemoteDesktop=gnome` or omits explicit overrides, because `xdg-desktop-portal` routes it to GNOME portal (which fails under Niri), trapping `kdeconnectd`. | Explicitly set `RemoteDesktop=none` and `InputCapture=none` in `niri-portals.conf` to force `kdeconnectd` to fall back to native `uinput`/`XTest` with `/dev/uinput` ACL permissions. |
| **KDE Connect Firewall Isolation on Local Wi-Fi** | Removing `kdeconnect` from the `public` zone in `firewalld` blocks UDP broadcast discovery (port 1714) and TCP connection (ports 1714-1764) on local wireless interfaces (`wlp*`), silently breaking pairing and device discovery. | Retain `<service name="kdeconnect"/>` in `etc/firewalld/zones/public.xml` to allow LAN discovery on wireless networks while maintaining firewall isolation. |
| **Monitor Alignment & Pointer Traps** | Defining monitor positions that only touch at a single logical point (e.g., corner-to-corner) or using auto-snapping features that disregard vertical layouts causes pointer traps. | 1. Ensure monitor boundaries share a logical edge (not just a vertex). 2. Disable third-party "monitor snapping" features (e.g., in DMS) when using vertical or custom layouts. 3. Validate KDL syntax (use `x=0 y=0`) to prevent fallback to automatic horizontal positioning. |
| **Shell Resource Instability** | Enabling real-time audio visualization in DankMaterialShell (DMS) causes ~60% CPU overhead and OSD ghost popups during IPC events. | **Disable** `audioVisualizerEnabled` and `soundVolumeChanged` triggers in `settings.json` to maintain shell stability. |
| **AccountsService Avatar Sandboxing & Symlink Mounts** | Setting user profile pictures (`SetIconFile`) fails with `is not a regular file` if the source image exceeds 1MB (`ICON_FILE_MAX_SIZE`) or resides in a directory symlinked to an external mountpoint (e.g. `~/Downloads -> /var/data/Downloads`) due to systemd `ProtectSystem=strict` sandbox restrictions. | Scale profile images to standard avatar resolutions (e.g. 512x512, <1MB) and stage them directly inside the native home directory (e.g. `~/.face` or `~/profile.png`) before invoking AccountsService. |
| **DMS-Greeter Cache Permission & OSTree Merge Trap** | Running greeters under unprivileged users (`greetd`) fails to read root-owned state in `/var/cache/dms-greeter` (`0700`). In addition, testing configs in `/etc` on bootc marks them as user modifications in ostree 3-way merge, shadowing upstream updates. | 1. Declare cache permissions in `/usr/lib/tmpfiles.d/dms-greeter.conf` (`d /var/cache/dms-greeter 0755 greetd greetd`).<br>2. Never leave manually modified files in `/etc` on atomic nodes; manage all configurations declaratively in container layers. |
| **Modular Desktop Input & Hardware Overlays in Niri** | Niri prohibits duplicate top-level `input` nodes and does not allow nested `include` blocks inside existing nodes. Defining machine-specific input peripherals directly in `config.kdl` violates base image agnosticism. Letting DMS write `input.kdl` while including it directly in `config.kdl` creates dual-writer race conditions and drops hardware bindings (`touch`, `tablet`, `trackpoint`). | 1. | **Fastfetch ASCII Art Corruption in Narrow Terminals (<90 cols)** | Verbose modules (`packages` with granular sub-package manager breakdown, `display` with panel hardware IDs, composefs disk overlay, and duplicate GTK2/3 fonts) exceed 85 columns. Narrow terminals wrap the text onto column 0, breaking and truncating the lateral ASCII logo. | 1. Enable `disableLinewrap: true` in `display`. 2. Compact `packages` (`{rpm} (rpm), {flatpak-all} (flatpak), {brew} (brew)`). 3. Set `compactType: original-with-refresh-rate` for the display module and shorten key names (`WM`). 4. Point `disk` to the real Btrfs partition and isolate modern GTK fonts (`{3}`). |
| **DMS Bar Window Actions & Wayland Compositor Controls** | Tiling Wayland compositors (like Niri) do not provide server-side decorations (SSD titlebars/close buttons). When `prefer-no-csd` is active or applications lack CSD headerbars, windows cannot be closed via mouse/touch. Quickshell/DMS cannot decorate foreign window surfaces directly via layer-shell. | Deploy a lightweight DMS bar widget (`type: "widget"`, `capabilities: ["dankbar-widget"]`) using `PluginComponent` with `pillClickAction` dispatching `Quickshell.execDetached(["niri", "msg", "action", "close-window"])`. | **Wayland Software KVM & Input Capture/Emulation Backend Alignment** | Non-standard or tiling Wayland compositors (such as Niri or wlroots-based MangoWC) do not implement full GNOME/KDE RemoteDesktop portals. Forcing portal backends when `InputCapture=none` traps input daemons. | Rely on compositors' native Wayland protocols (`wlr-virtual-pointer-unstable-v1`, `virtual-keyboard-v1`) for input emulation and `layer-shell` for edge capture fallback, ensuring seamless cross-device sharing across heterogeneous Wayland environments. |
| **DMS Control Center Plugin Toggle Integration** | Custom system or background service toggles (e.g. software KVM sharing) lack out-of-the-box UI switches in the DankMaterialShell Control Center. | Implement a DMS plugin declaring capability `control-center` using `PluginComponent` with reactive `Process` status polling and toggle execution. Register `plugin_<pluginId>` in `controlCenterWidgets` inside `settings.json` and persist the plugin in `/etc/xdg/quickshell/dms-plugins/`. |
| **Niri Monolithic Binds vs DMS Keybind Management** | Niri strictly prohibits duplicate top-level `binds` blocks (`duplicate node 'binds', single node expected`). Keeping keybindings hardcoded inside `config.kdl` while including `dms/binds.kdl` marks all bindings as `"source": "config"` instead of `"source": "dms-default"`, hiding them from DMS GUI override management and causing validation crashes if DMS attempts to write bindings. | Segregate the entire `binds { ... }` block into a dedicated include file (`dms/binds.kdl`) included by `config.kdl`. For zero-prompt biometric boots, configure `login.keyring` with an empty password in Seahorse. |

Execute greeters in standard self-contained mode (`dms-greeter --command <wm> -C <config>`).<br>2. Rely on default shared cache (`/var/cache/dms-greeter`) for theme/wallpaper state synchronization.<br>3. | **KDE Connect Remote MPRIS Session Desync & Media Stalls** | Wayland MPRIS daemons exposing dead player D-Bus interfaces cause KDE Connect to broadcast stale playback status. Incoming remote control packets to closed players trigger unhandled timeout exceptions in mobile clients. | 1. | **DMS-Greeter QML Silent Patch Failure** | Executing string replacement on QML files without verifying target string presence causes silent patch degradation when upstream QML files change layout or syntax. | Always raise an explicit error (`raise SystemExit(...)`) if the replacement target is not found in the source file during container build scripts. |
| **XDG Autostart & Wayland System Tray Race Condition** | Autostarting background tray apps (Nextcloud, Tailscale, NetworkManager applet) before the Wayland compositor or shell status notifier (`StatusNotifierWatcher`) claims D-Bus ownership causes tray icons to fail silently or fallback to invisible X11 windows. | 1. | **Single-Node KDL Collision in Overlays (`focus-follows-mouse`)** | Niri enforces single-instance cardinality on scalar input options (`single node expected`). Declaring desktop options in hardware overlay templates (`input-hardware.kdl`) causes duplicate nodes when DMS settings also inject them into `dms/input.kdl`, crashing the parser. | 1. Strip UI-configurable desktop options (`focus-follows-mouse`) in `bolina-daemon input-sync` before injection. |
| **Layer-Shell Wayland Touch Seat Desync (Quickshell / DMS)** | Repeated compositor config reloads, screen rotations, or display geometry changes trigger dynamic surface recreation (`SurfaceRecovery`) in long-running QtWayland/Quickshell processes. While `wl_pointer` (mouse/trackpoint) continues dispatching clicks, the Wayland `wl_touch` seat can drop input bindings to recreated top-docked layer-shell surfaces without crashing the process. | Execute a non-destructive shell restart (`dms restart`, sending `SIGUSR1` to cleanly cycle the user-space Quickshell process) to re-bind Wayland touch seats from a clean socket connection without disrupting running application windows or compositor sessions. |

## 3. Packaging, Sandboxing (Flatpak) & Container Runtimes

| Error Class / Technical Challenge | Root Cause (Abstract) | Preventive Action / Architectural Pattern |
| :--- | :--- | :--- |
| **Package Source & Namespace Integrity** | Assuming package availability, naming, or external installer flags without verification. Third-party COPRs often diverge from standard Fedora naming conventions (e.g., missing `-modules-extra`). | 1. **Verify** exact package names via `dnf list` simulation or official repo search. 2. For GitHub releases, check actual asset names. 3. When switching from RPM to standalone binaries, **always** manually provide missing systemd units (`.service`, `.timer`) and config files previously included in the package. |
| **Transition Package Naming** | Assuming package names based on previous versions (e.g., KF5 vs KF6) leads to non-existent package errors. | Always verify exact package names on the target host or official repositories, especially for toolkit-specific libraries. |
| **Protected Package Swap Constraints (DNF5)** | DNF5 prevents the removal of critical packages (e.g., `sudo`) defined in `protected_packages` even if a replacement is provided in the same transaction. | Use `--setopt=protected_packages=` to temporarily clear the protection list during the swap transaction. Prefer a single transaction with `--allow-erasing`. |
| **Bootc User/Group Conflicts** | Creating system users or groups in `/etc/passwd` at build time triggers 3-way merge conflicts and UID drift during bootc upgrades. | Segregate all build-time created users and groups (except root/wheel) to `/usr/lib/passwd` and `/usr/lib/group`, relying on the `altfiles` NSS backend for runtime resolution. |
| **Third-Party Repository Validation** | Relying on unverified URLs or corrupted GPG keys for external repositories causes build failures. | Always verify raw repository configuration files and check URL accessibility (e.g., via `curl -I`) before integration. |
| **Plugin Dependency Resolution** | Software plugins often depend on low-level CLI utilities that are not included in base images. | Audit plugin source code or documentation to identify and explicitly install all required system-level CLI dependencies in the build manifest. |
| **Configuration Include Integrity** | Modular configuration files using `include` statements will fail if any referenced path is missing. | Ensure all included configuration fragments exist in the repository, using empty placeholders if necessary. |
| **Config Redirection Corruption** | Using append (`>>`) on configuration files without checking for existing sections causes "duplicate key" syntax errors. | **Always** verify file content before redirecting or use structured editing (e.g., `sed` or `yq`) to modify existing configuration blocks. |
| **Application ID Mismatch** | Linking services using assumed IDs instead of verified Flatpak IDs causes MIME and Portal failures. | **Always** align symlinks and MIME integrations with official IDs. Use shadow `.desktop` files for internal app checks if needed. |
| **Flatpak Remote Persistence & Indexing** | In atomic systems, simply adding a remote configuration file may not trigger metadata indexing. | Use a hybrid approach: add the `.flatpakrepo` file to `etc/` **and** run `remote-add` + `update --appstream` during the build to warm the cache. |
| **Atomic System GPG Keyring Constraints** | Initializing a remote via URL during build may fail if the GPG key is not yet trusted. | Point the initialization command to a local `.flatpakrepo` file that already contains the GPG key to ensure atomic import and trust. |
| **Sandboxed App Discovery** | Placing `.desktop` files in non-standard paths prevents detection of sandboxed applications (Flatpaks). | Ensure all application entries are placed in or linked to standard XDG paths verified by the desktop environment. |
| **Duplicate Flatpak Icons** | Creating manual symlinks for Flatpak `.desktop` files in `XDG_DATA_DIRS` causes duplicate launcher entries. | **Do not** manually link Flatpak-exported desktop files; rely on standard export paths or use `flatpak override`. |
| **Flatpak Display Server Socket Restriction (`QT_QPA_PLATFORM`)** | Setting `!wayland` or revoking `x11` access (`sockets=!x11` or `sockets=fallback-x11;!wayland`) for Flatpak applications configured with `QT_QPA_PLATFORM=xcb` running on Wayland compositors (e.g. Niri) blocks access to both display backends, causing Qt initialization failure (`qt.qpa.xcb: could not connect to display`) and immediate application crash. | Ensure hybrid/Qt Flatpak applications maintain both `sockets=wayland` and `sockets=x11` permissions in overrides when running under Wayland compositors with Xwayland active. |
| **Flatpak & Chromium Browser VA-API Decoding (`--use-gl=egl` Deprecation)** | Chromium-based browsers disable GPU-accelerated video decoding by default on Linux/Wayland. Furthermore, in modern Chromium (124+), passing legacy `--use-gl=egl` conflicts with ANGLE (`(gl=egl-gles2,angle=none) not found in allowed implementations`), causing the GPU process to crash on startup and fall back to `--use-gl=disabled` (full software rendering). | Create a `%s-flags.conf` file (e.g. `brave-flags.conf`) with `--ozone-platform-hint=auto`, `--enable-features=VaapiVideoDecoder,VaapiVideoDecodeLinuxGL,AcceleratedVideoDecodeLinuxGL`, `--ignore-gpu-blocklist`, `--enable-gpu-rasterization`, and `--enable-zero-copy`. **Omit** `--use-gl=egl` to allow Chromium's native ANGLE/EGL backend to initialize. |
| **Container User Symlinks & XDG Directory Resolution** | Symlinking `$HOME` subdirectories into container mounts without initializing canonical target structures triggers runtime traversal errors (`EEXIST`/`ENOENT`) in sandboxed desktop applications. | Explicitly create target directories in `05-system-config.sh` before creating user skeleton symlinks in `/etc/skel/`. |
| **Rust Drop-in Activation & Dynamic Multicall Symlinking** | Hardcoding symlink lists for multicall binaries (like `uutils-coreutils`) causes maintenance drift when upstream releases add newly implemented utilities, while overwriting files in `/usr/bin` triggers conflicts with RPM database tracking during atomic OSTree/bootc tree-compose. | Expose multicall utilities dynamically via `/usr/local/bin` using `for cmd in $(/usr/bin/uutils-coreutils --list); do ln -sf /usr/bin/uutils-coreutils "/usr/local/bin/$cmd"; done`. Because `/usr/local/bin` sits ahead of `/usr/bin` in standard `$PATH`, interactive shells and user scripts transparently execute Rust drop-ins while preserving original GNU binaries in `/usr/bin` for system packaging internals. |
| **System Shared Library ABI Boundary vs Rust Binary Drop-ins (`libcurl` Trap)** | Swapping shared C libraries that provide critical OS-level ABIs (e.g. `/usr/lib64/libcurl.so.4` with OpenSSL bindings consumed by `dnf5`, `bootc`, `ostree`, and `crun`) for alternative implementations or non-ABI-compatible TLS backends risks destabilizing atomic host updates and package transactions. | Confine Rust drop-in replacements strictly to standalone CLI binaries, multicall tools, and system daemons (`uutils-coreutils`, `uutils-findutils`, `ntpd-rs`, `sudo-rs`) rather than system shared libraries. |
| **Premature Drop-in Adoption & Arbitrary SemVer Assumptions** | Assuming software projects (such as uutils rewrites) are complete drop-in replacements based on tag releases or SemVer numbers leads to broken CLI tooling (e.g. diffutils lacking `-r`). Version numbers (even <1 or >=1) are subjective and do not guarantee POSIX/GNU CLI parity. | Never integrate candidate drop-in replacements into the OS without explicit manual verification of full CLI flag parity or official distribution packaging (e.g. Fedora stable repos). Exclude WIP projects (e.g. diffutils, sed, grep) from system drop-in paths entirely until verified. |
| **Flatpak Emulator Input Device Profile Mismatch** | Emulators running in Flatpak sandboxes default to dummy or keyboard input profiles (`XInput2/0/Virtual core pointer`) when new controller hardware is attached, ignoring physical Gamepad input (`evdev`/`SDL`) despite valid host udev/ACL permissions. SDL2 subsystem device names also diverge from kernel strings. | 1. Query the exact runtime SDL device string using `SDL_JoystickNameForIndex` inside the container context. 2. Configure explicit SDL/evdev input profile mappings in app config directories (`~/.var/app/<app_id>/config/`) using the verified string (e.g. `SDL/0/<exact_sdl_name>`) and ensure sandbox `devices=all` or `/dev/input` permissions are active. |
| **Stale FUSE Document Portal Mount** | FUSE mount at `/run/user/<uid>/doc` disconnects (e.g. after sleep/resume or FUSE I/O error), but `xdg-document-portal.service` stays active on D-Bus without auto-restarting. `bwrap` fails with `Can't find source path .../by-app/<app_id>`. | Restart `xdg-document-portal.service` via `systemctl --user restart xdg-document-portal.service` or add a systemd sleep hook / health check to remount FUSE automatically upon resume. |
| **Single-Instance Application Lock/Socket Stale State** | Abrupt application termination or system crashes leave orphan single-instance IPC sockets (`ipc-socket`) and lock files (`lockfile`) in app config directories (`~/.var/app/<app_id>/config/`). Subsequent launches detect these files, mistake the environment for a running process, send IPC signals to a dead socket, and exit silently with code 0. | Verify with `ps` that no real application process is running, then remove orphan `lockfile` and `ipc-socket` files from the application configuration directory to restore launch capabilities. |
| **Immutable Path Conflict in Distrobox** | Extracting archives to shared system paths (e.g. `/usr/local/share`) inside containers fails when the container engine mounts host system asset paths read-only (common in Atomic OS). | Extract to isolated, writable directories (e.g. `/opt/<tool>`) and only symlink the final executable to `/usr/local/bin`. |
| **Topgrade NPM Symlink Conflict** | `topgrade` automatically detects and updates `npm` globally. If `npm` is a Homebrew dependency, it conflicts with Homebrew's symlinks in `share/man`. | Disable `npm` in `topgrade.toml` to let Homebrew manage its own dependencies exclusively. **Note**: When using a custom `topgrade.toml`, you MUST explicitly set `bootc = true` in the `[linux]` section for Atomic systems. |
| **Persistent Home Overrides** | System-wide MIME associations in `/etc/skel` are ignored if the user has a pre-existing `~/.config/mimeapps.list`. | Use systemd setup services to explicitly patch existing user configuration files in `/var/home` if a default must be enforced. |
| **Shell Configuration Drift** | Placing critical CLI tool initializations in `/etc/skel` fails to update existing users during image upgrades. | Move system-wide shell initializations (interactive features, aliases) to `/etc/fish/conf.d/` or equivalent system paths to ensure all users receive updates. |
| **Shell Alias vs Subprocess Invocation** | Interactive shell aliases (e.g. in `/etc/fish/conf.d/` or `~/.bashrc`) are not expanded in non-interactive subshells spawned by desktop daemons or scripts. Depending on an alias (`agy`) instead of a canonical binary (`antigravity`) causes silent execution and credential-refresh failures. | Deploy standard executable symlinks to `~/.local/bin` or `/usr/local/bin` and always implement fallback binary resolution (`command -v alias_cmd || command -v canonical_cmd`) in scripts. |
| **Fish Path Precedence & Binary Shadowing** | Using `fish_add_path` without `--append` puts external package manager paths (Homebrew) at the front of `$PATH`, enabling unprivileged tools to shadow `/usr/bin` system executables. | Always pass `--append` to `fish_add_path` for user-managed external runtimes to ensure root/system binaries retain execution priority. |
| **User-Level Automation Consistency** | Global system services cannot access user-home resources (like `~/Downloads`) due to security boundaries. Placing user units in `/etc/skel/` prevents `systemctl --global enable` from finding them during build. | Deploy user-level systemd units to `/etc/systemd/user/` (not `/etc/skel/`) and enable them using `systemctl --global enable` in the build manifest. This ensures the service is active by default for all user sessions. |
| **Non-Interactive Background Upgrades & Sudo Privileges (`topgrade`)** | Executing full-system upgrade orchestrators like `topgrade` non-interactively via user systemd timers fails at the OS layer (`sudo bootc upgrade`) with `interactive authentication is required` due to lack of an interactive TTY for password prompts. | Deploy a dedicated sudoers drop-in `/etc/sudoers.d/99-bootc-topgrade` granting `%wheel ALL=(ALL) NOPASSWD: /usr/bin/bootc upgrade` (permissions `0440`). Orchestrate full-system updates (Flatpak, Brew, Distrobox, firmware, plugins, and bootc) via a user systemd timer (`topgrade.timer`). |
| **Monotonic Timer Sleep Freeze on Laptops** | Systemd timers defined with monotonic intervals (`OnUnitActiveSec=`) pause during laptop suspend/sleep. Setting `Persistent=true` has no effect because persistence applies exclusively to real-time calendar timers (`OnCalendar=`), causing hourly maintenance jobs to stall indefinitely across sleep cycles. | Convert periodic maintenance jobs on portable devices to calendar timers (`OnCalendar=hourly` or `*-*-* *:00:00`) with `Persistent=true` so missed runs execute immediately upon wake. |
| **Qt6 Declarative QML Submodule Packaging Mismatch** | Fedora RPM packages split Qt6 into granular sub-packages (`qt6-qtdeclarative`, `qt6-qtwayland`, etc.). Omitting runtime QML imports (e.g. `QtQuick.Layouts`, `QtWayland.Compositor`) causes apps to compile successfully but crash with `module "..." is not installed` at runtime. | Audit all QML `import` statements across application trees and verify package providers via `dnf repoquery --whatprovides "qt6-*-devel"` before building container layers. |
| **Autostart Application Foreground Window Spawning** | Autostart desktop entries invoking GUI frontend executables (e.g. `kdeconnect-app`) or missing background startup flags (e.g. `--background` for Nextcloud Flatpak) force interactive windows to open directly on the screen at session launch. | Target background indicator daemons (`kdeconnect-indicator` or headless `kdeconnectd`) and append `--background` to container/desktop invocations to ensure silent tray startup. |
| **Global User Systemd Unit System Account Trap (`ConditionUser=!@system`)** | Enabling user systemd services or timers globally (`/etc/systemd/user/` or `systemctl --global enable`) causes them to spawn inside `systemd --user` instances of lingering system accounts (such as `greetd` for display greeters or daemons with `/var/lib/systemd/linger/<user>`). For tasks requiring interactive shells, user environments, or home directories (e.g. `topgrade`, Taildrop auto-receive), these units fail with error exit codes or spawn useless daemon loops. | Add `ConditionUser=!@system` in the `[Unit]` section of all user systemd units deployed to `/etc/systemd/user/` that should only execute for interactive/human users (UID >= 1000). |
| **Distrobox Chromium/Brave Flag Injection & MIME Desync** | Distrobox browser RPMs (`/usr/bin/brave-browser-stable`) ignore user flag configs (`~/.config/brave-flags.conf`), launching with unaccelerated defaults on Wayland. Exported `.desktop` entries also fail to register as default handlers without explicit XDG MIME bindings. | 1. Implement wrapper script (`~/.local/bin/brave-browser`) parsing `~/.config/brave-flags.conf` and forwarding to `distrobox-enter -n <container> -- <binary>`.<br>2. Update exported desktop `Exec=` paths.<br>3. Set defaults via `xdg-settings set default-web-browser <desktop_id>` and `xdg-mime default <desktop_id> x-scheme-handler/http[s]`. |

## 4. Kernel, Hardware Acceleration, Power & Audio

| Error Class / Technical Challenge | Root Cause (Abstract) | Preventive Action / Architectural Pattern |
| :--- | :--- | :--- |
| **Kernel Install Dracut Failure** | DNF attempts to regenerate the initramfs via `dracut` during kernel installation, which fails in containers due to missing `modules.dep` or environment context. | Disable automatic generation by creating `/etc/kernel/install.conf` with `initrd_generator=none` before installation. Then, manually run `depmod` and `dracut` after the RPM transaction. |
| **Multiple Kernels in Bootc Lint** | `bootc container lint` fails if multiple kernel versions are found in `/usr/lib/modules/`. | Explicitly remove all existing kernel packages and wipe `/usr/lib/modules/*` before installing a new custom kernel. |
| **Containerized GRUB Probing** | Post-install scripts of kernel/grub RPMs fail in containers as they cannot resolve the canonical path of the `overlay` filesystem. | **Mock** `grub2-probe` and `grub2-editenv` in a temporary directory (e.g., `/tmp/bin`) and prepend it to the **PATH** during the `dnf` transaction to override standard system binaries. |
| **Global VA-API Driver Pinning vs Multi-Vendor GPUs** | Setting `LIBVA_DRIVER_NAME=iHD` globally in `/etc/profile.d/` or `/etc/fish/conf.d/` forces Intel Media Driver across all systems, breaking video acceleration on AMD (Radeon) or Nvidia hardware running the base image. Case sensitivity also matters (`iHD` vs `ihd`). | Avoid setting `LIBVA_DRIVER_NAME` in the generic base image, allowing `libva` to auto-detect the appropriate driver via PCI ID. Confine specific driver overrides (`LIBVA_DRIVER_NAME=iHD`) strictly to hardware-specific downstream layers in `bolina-fleet`. |
| **ZRAM Swappiness Inversion & Page Clustering** | Using legacy low swappiness (`vm.swappiness = 10`) with ZRAM starves in-memory compression and forces the kernel to aggressively evict filesystem page caches, causing heavy disk I/O latency. | Set `vm.swappiness = 130` and `vm.page-cluster = 0` so the kernel compresses inactive anonymous memory into ZRAM while keeping executable code caches in physical RAM. |
| **Disk-Specific I/O Scheduling** | Generic I/O scheduler rules may apply sub-optimal schedulers to rotating vs. non-rotating drives. | Use explicit udev rules checking `ATTR{queue/rotational}` to apply `bfq` to HDDs and `adios` (or similar) to SSDs/NVMe for optimal responsiveness. |
| **USB Storage Topology vs SCSI Removable Flag** | Filtering USB storage using solely the SCSI `RM` (Removable Media) flag or sysfs `removable == 1` causes detection failures on modern external SSDs, USB 3.x flash drives, and Linux gadget devices (like e-readers/Kobo) which register with `RM=0` (fixed disk). | Identify external drives by checking the bus transport topology (e.g. `TRAN =~ ^usb` in `lsblk` or sysfs parent path matching `*/usb*`) rather than relying on the media removable bit. |
| **Low-TDP iGPU Emulator Throttling & Watcher False Positives** | Emulators on low-TDP iGPUs (15W RAPL PL1) downclock CPU cores (~1.2GHz) under heavy shader load. Custom frontends bypass `.desktop` wrappers, while systemd user services fail if D-Bus tools lack `PATH`. Broad matching (`pgrep -f`) triggers false-positive power switches on package indexing, and 1s poll loops prevent CPU deep C-states. | 1. Use native `powerprofilesctl` with explicit `PATH` in watcher scripts (`dolphin-power-monitor.sh`) to toggle `performance` mode.<br>2. Target exact binary names (`pgrep -x "dolphin-emu"`) with relaxed intervals (2-3s).<br>3. Enable async shader compilation (`ShaderCompilationMode=1`, `SkipShaderCompilation=True`) and audio stretching (`AudioStretch=True`) to offload GPU, letting CPU boost to 3.0GHz+. |
| **SCX vs Ananicy-cpp Conflict** | Running both an eBPF scheduler (SCX) and a priority daemon (Ananicy) causes "priority fighting". Firefox/Browsers experience multi-second hangs during media initialization. | **Never** run Ananicy-cpp alongside SCX. Modern eBPF schedulers handle process priorities natively at the kernel level. |
| **TLP vs SCX/P-State Latency** | TLP's aggressive power saving on battery limits CPU scaling, which conflicts with SCX's high-frequency scheduling demands. This causes UI stuttering and browser lag. | Use **power-profiles-daemon** instead of TLP. It integrates natively with the kernel P-State driver and modern desktop environments/schedulers. |
| **eBPF Overhead & Kptr Incompatibility on Battery (SCX)** | Starting eBPF schedulers (SCX) by default on battery increases power consumption due to context-switch overhead and risks kernel crashes if the SCX binary diverges from the running kernel BPF API. | **Do not** enable `scx.service` by default on battery-operated laptops. Rely on the native kernel scheduler for baseline stability, starting SCX manually when high-throughput scheduling is needed. |

## 5. Security, Firewall & Network

| Error Class / Technical Challenge | Root Cause (Abstract) | Preventive Action / Architectural Pattern |
| :--- | :--- | :--- |
| **Secret Exposure in Config Files** | Committing plain-text credentials (WiFi PSK, EAP identities) in NetworkManager `.nmconnection` files leaks secrets to public repositories. | **Never** commit files containing actual secrets. Use `.gitignore` for local configurations and provide only sanitized templates if necessary. |
| **Firewall Over-Exposure** | Enabling SSH on the `public` zone by default increases the attack surface for remote brute-force. | Keep `ssh` disabled in the default `public` zone. Users should enable it explicitly or use a more restrictive zone/VPN. |
| **VPN vs Physical Network Firewall Segmentation** | Exposing desktop control services (KDE Connect, media RTSP) in the default `public` firewalld zone leaks listening ports on untrusted LANs. | Confine inter-device services to the encrypted VPN interface (`tailscale0`) mapped to the `trusted` zone, maintaining standard restrictive filtering on public Wi-Fi interfaces. |
| **P2P Network Display Firewall Isolation** | On atomic OS, Flatpak applications like GNOME Network Displays encounter RTSP/P2P port blocks by firewalld and Wi-Fi scan rejections by `wpa_supplicant` due to MAC address randomization. | 1. Declare firewalld zone `etc/firewalld/zones/P2P-WiFi-Display.xml` with `<zone target="ACCEPT">` for ports 7236/tcp, 7250/tcp and dynamic streams. 2. Configure `etc/NetworkManager/conf.d/10-p2p.conf` disabling `wifi.scan-rand-mac-address` and binding `wifi-p2p` devices to the `P2P-WiFi-Display` zone. |
| **Polkit UX vs Security Conflict** | Enforcing `AUTH_ADMIN_KEEP` on frequent background operations (like USB mounting, app updates, or dynamic kernel scheduling) introduces excessive password prompts that break the frictionless desktop experience. | Use `Result.YES` for trusted local tools (e.g., udisks, flatpak, scx) where UX priority supersedes strict isolation boundaries. Ensure group restriction (e.g., `isInGroup("wheel")`) is maintained. |
| **Polkit JS API Property Misreference (`action.details` Crash)** | Referencing `action.details.<key>` instead of `action.lookup("<key>")` in Polkit JavaScript rules evaluates `undefined.<key>`, raising an unhandled `TypeError` in `polkitd`. Because Polkit evaluates all rules in a single JS context, this unhandled exception aborts authorization processing for all subsequent callers (including GUI tools and `pkexec`), manifesting as unexpected `Not authorized [TTY=unknown]` failures. | Always use `action.lookup("key")` to query action metadata in Polkit rules. Guard lookups with null-checks before accessing properties or methods (e.g., checking `action.lookup("command_line")` before `.indexOf()`). |
| **TCP Fast Open Latency Elimination** | Modern web protocols incur a full round-trip delay on initial connection handshake. | Enable `net.ipv4.tcp_fastopen = 3` and set `net.ipv4.tcp_slow_start_after_idle = 0` to shave round-trip latency off initial HTTP/TLS requests. |
| **Software KVM Mesh VPN Confinement (Tailscale vs LAN Exposure)** | Exposing input sharing/KVM ports (e.g. `lan-mouse` UDP 4242) directly on the physical `public` firewalld zone leaks raw remote control listening ports on untrusted local networks. | Keep public firewalld zones closed and route cross-device KVM communication strictly through the virtual encrypted mesh interface (`tailscale0` in `trusted.xml`). Package firewalld definitions (`etc/firewalld/services/lan-mouse.xml`) declaratively without binding them to public physical adapters. |

## 7. System Diagnostics, Triaging & Operational Heuristics

| Error Class / Technical Challenge | Root Cause (Abstract) | Preventive Action / Architectural Pattern |
| :--- | :--- | :--- |
| **Inverted Diagnostic Triage (Bottom-Up vs Top-Down Trap)** | Jumping prematurely into kernel drivers, ACPI tables, or compositor C++ source when debugging UI popups or D-Bus state changes bypasses the primary culprit: userland scripts, timers, and desktop environment hooks executing CLI tools (`powerprofilesctl`, `wpctl`, `dconf`). | **Strict Triage Order:** 1. Search `~/.local/bin/`, `~/.config/systemd/user/`, and `~/.config/autostart` for invocations of controlling CLI tools.<br>2. Inspect user-space daemon configs (`~/.config/`).<br>3. Escalate to daemon source or kernel registers only after ruling out userland triggers. |
| **Boot Journal Negative Time Jumps (RTC vs NTP/chrony Misalignment)** | Motherboard hardware clocks (RTC) out-of-sync with UTC/local time produce a negative or positive time step when `chronyd` synchronizes network time during early boot. Passing absolute `--since` timestamps matching the post-sync timeline causes `journalctl` to return `-- No entries --`, falsely suggesting that early boot services never executed. | When triaging boot sequences, avoid absolute `--since` filters. Rely instead on relative boot selectors (`journalctl -b 0`, `-n <N>`, `-o short-iso`, or pipe to `head`/`grep`) to capture logs irrespective of hardware clock synchronization steps. |
| **Quickshell / DMS Proprietary Binary Log Inspection (`.qslog`)** | Quickshell and DankMaterialShell do not emit plain-text logs to standard disk paths; they write compressed binary `.qslog` files under `/run/user/<uid>/quickshell/by-id/<instance-id>/`. Direct inspection via standard text tools fails with unsupported binary MIME type errors. | Identify the active instance with `quickshell list --all` and query the binary stream using `quickshell log <instance-id>` or `quickshell log /path/to/log.qslog`. |
